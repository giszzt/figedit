# 勘察与重建路径（Survey & Reconstruction Path）

**何时读我**：每个任务的第一步。本文件是勘察协议、重建路径概要和 `reconstruction_plan` 的唯一权威。背景执行细节见 `background_reconstruction.md`，元素语义见 `element_decision_matrix.md`。

## 四来源指派

输出画面上的每一块像素只可能有四个来源：

1. **SVG 画的** —— 结构、文字、公式
2. **从源图切的** —— `crop`
3. **AI 生成的** —— 区域清版底（背景）、色键版再生（前景对象）
4. **整块原样保留的** —— `preserve-raster`

勘察就是给每一部分指派来源，每部分有且只有一个。指派完成即可开工；有部分没被指派，说明漏看了。

复杂度不决定来源。决定来源的是三件事：背景能不能机械恢复、对象能不能干净分离、用户需要编辑什么。

## 勘察怎么做

**先分区定底子，再成批扫对象。**不要拿着一个对象走完整条决策链再看下一个。

1. 把画面按视觉场性质分区。多面板图按面板分，整幅一致的图就一个区。
2. 每个区判底子的来源：平色或规则渐变→SVG 画；连续场且内部有待编辑前景→AI 清版；连续场但内部不需要改→整块保留。
3. 各区里过不了重绘门槛的对象一次扫完，分成"可直接切"和"被压盖"两堆。
4. 记下公式有无、工作量重心、要问用户的事。

第 2 步用 SKILL.md 的图型速查表按区查，比逐条推导快。判不准时回到四来源指派。

### 底子判据

- **SVG 画**：纯色、简单单区渐变、可测量的规则几何。
- **AI 清版**：照片、地图、插画、纹理或渲染场里压着待编辑的文字、路线、标记或图标，移除它们会暴露未知像素。区域可以是整幅画布，也可以只是一个面板或一块地图框。
- **整块保留**：截图、地图、照片、图表主体边界完整，内部没有需要移除或编辑的前景。这种保留不需要为保留本身提问。

只要区域内部存在待编辑前景，就不得静默改成整区保留。用户明确接受"该区域整体保持不可编辑栅格并保留旧标注"时才可以。

区域坐标在勘察阶段一个都不写，备料阶段量。

### 对象两堆的判据

先过重绘门槛（SKILL.md 正文）。过不了的做一次负向污染扫描，任一成立即归"被压盖"那堆：

- 轮廓被文字、箭头、卡片边框、分隔线、徽标或邻居穿过、遮住。
- 最小外接矩形不可避免地含有其他对象的像素。
- 与承载面边框、圆角、阴影或连续背景纹理相交。
- 对象自身有缺口，需要猜相邻背景才能补全。

"被压盖"这堆再看一个问题：**需不需要单独动？**需要就再生（`regenerate-chroma`），不需要且落在清版区就压平进底板（`flatten`）。确定性 SVG 区没有底板可承载，那里的污染对象只能再生。

四个来源之外还有一种情况：对象必须像素级保真、又不可分离、AI 近似不可接受。这时让用户在整区栅格保留和保真损失之间选，不要静默降级。

精确边界和净空由 `snap_boxes.py` 在备料阶段量。勘察只负责把对象归堆，不做像素判断，也不先裁小图试错。

## 重建路径概要

勘察的唯一交付物，纯文字，零坐标，二十行以内。六个槽位，缺项写"无"。

| 槽位 | 写什么 |
|---|---|
| 图型与分区 | 每区一行：这是什么、底子从哪来 |
| 需要生成的 | 清版底张数 + 色键版张数 = 计费调用总数 |
| 不可重画的对象 | 可直接切的一堆、需再生的一堆，按名字和位置点出来 |
| 公式 | 有无、大致数量 → 验证档位 |
| 工作量重心 | 时间主要花在哪 |
| 需要用户定 | 具体问题 |

生成预算按确定算法估：每个 AI 区域计 1 张清版底；有再生候选时默认 K=2 张不同键色 sheet，整图已明显证明一种安全键色覆盖全部候选时才写 K=1 并说明依据。总数 `N = 清版底数 + K`，声明这是勘察估计。用户确认后再用 `probe_palette.py --boxes` 确认实际 K；实际会超预算时先重新告知，不得静默增加调用。

### 范例一：多面板复合图

```
图型与分区    (a)(b) 面板  平色底，SVG 重建
              (c) 地图区   连续场，标注压在地图像素上 → 区域清版
              (c) 下方列表 平色底，SVG 重建
需要生成的    地图区清版底 1 张 + 污染图标色键版 1 张 = 2 次计费调用
不可重画的对象
  可直接切    难度/场景/反馈三个图标、导航机械臂相机三件、法槌机器人、
              文档堆、good/bad case、底部定位针与气泡
  需再生      地球仪（骑在面板边框上）、笔记本人像（贴框线）、
              大机器人（压出框）、Cluster/Analyzer/Refiner/Validator（虚线回路穿过）
公式          A^E、A^S、a₁a₂a₃、θ，约 6-8 个 → pptx-triggered
工作量重心    一百一十来个文字标签的槽位排布，不是图标分类
需要用户定    (c) 地图标签要不要可编辑？要则清版，不要则整块保留，差一次生图
```

### 范例二：整幅连续场，用户要求仅文字可编辑

```
图型与分区    整幅是一张渲染星空场景，标题与说明文字压在上面 → 全图清版
需要生成的    清版底 1 张 = 1 次计费调用
不可重画的对象  无。用户锁定 text-only，图形对象全部压平进底板
公式          无 → svg-primary
工作量重心    文字分层与字重匹配，深色底上的描边处理
需要用户定    无。用户原话已锁定编辑深度
```

第二例没有裁剪、没有吸附、没有 inventory，整个备料只有 OCR 加一次生成。概要长什么样由图决定，不套模板。

## 用户检查点

任何清版区域的前景深度无法从用户原话确定时，把问题写进概要的"需要用户定"，一次问完并停止。一次提问同时给出：需要清版的具体区域和区内对象清单、`flatten / selective / full-extract` 的结果差异、生成预算数字、含公式时的 PowerPoint 附着预授权请求、你的推荐和理由。

编辑深度对照：

| 用户表达 | `edit_scope` | 连续场前景模式 |
|---|---|---|
| "仅文字可编辑""只改文字""翻译文字" | `text-only` | `flatten` |
| "文字、公式和框线可编辑" | `text+structure` | 图形对象深度可能仍待确认 |
| 点名对象需要移动或替换 | `selective-assets` | `selective` |
| "全部对象可移动/替换/完全打散" | `full-extract` | `full-extract` |

用户未说明编辑深度但检出公式时默认 `text+structure`，公式写成独立 `math`，验证档 `pptx-triggered`。用户明确 `text-only` 时不扩大结构重画范围，但公式仍保持可编辑，除非用户明确允许压平。

用户确认前不得发起计费生成调用，不得裁剪或合成。**OCR 不受此限**——它不计费、输出无论走哪条路都要用，可以和提问并行发出。检查点前不得运行 `probe_palette.py`。

## 备料阶段的执行输入

### `work/inventory.json`

只是喂给 `snap_boxes.py` 的执行输入，**只含走切或再生的对象**。文字框来自 OCR，结构框在组装时确定，都不进来。纯清版压平的图可以完全没有这个文件。

```json
{
  "image": "input.png",
  "objects": [
    {"id": "icon-robot", "bbox": [412, 188, 96, 90], "kind": "icon", "route": "crop"},
    {"id": "icon-globe", "bbox": [330, 452, 60, 58], "kind": "icon", "route": "regenerate-chroma"}
  ]
}
```

`bbox` 是一眼精度的粗框，允许 10–20px 偏差。此时路线已由概要锁定，点框是执行动作，不重新决定路线。`route` 取 `crop | regenerate-chroma | flatten`，其余路线的对象不写进来。

### `reconstruction_plan`

写 manifest 时记录的结论存档，不是勘察阶段的门。

```json
{
  "reconstruction_plan": {
    "edit_scope": "text+structure",
    "background_regions": [
      {
        "id": "panel-c-map",
        "source_region": {"x": 1200, "y": 55, "w": 478, "h": 600},
        "strategy": "ai-clean-plate",
        "foreground_mode": "flatten",
        "reason": "标注压在连续地图像素上"
      }
    ],
    "validation_tier": "pptx-triggered",
    "open_questions": [],
    "closeup_ids": [],
    "inventory": "figure-task/work/inventory.json"
  }
}
```

- `edit_scope`：`text-only | text+structure | selective-assets | full-extract`。
- `background_regions`：只登记 AI 清版区，以及**用户明确同意放弃内部编辑**的连续场保留区（`strategy` 为 `ai-clean-plate | source-preserve-region`），AI 区必须写 `foreground_mode`。SVG 区不登记。内部本就无需编辑的自包含截图、图表、地图整块保留时也不登记——它只是一个 `decision: "crop"` 或 `preserve-raster` 的资产，走资产字段即可。
- `open_questions`：非空即阻塞，此时不得存在 assets 或 background_plans，脚本会拒绝裁剪与合成。这是概要里"需要用户定"的机器可读副本，作兜底用。
- `closeup_ids`：需要 1:1 局部确认的区域。
- `inventory`：对象清单路径，validator 用它交叉检查 `assets[].decision`。

区域最终执行与验收写顶层 `background_plans[]`，用 `scope_id` 关联 `background_regions[].id`。旧 manifest 的 `route_decision` 继续兼容读取，新任务不再写它。

## 历史 manifest 复用

同源图历史产物只能复用 OCR 文本、公式内容、面板边界和已验证坐标。每次重新生成：重建路径概要、`reconstruction_plan`、`background_plans`、`assets[].decision` 与 `crop_window`、旧质量状态。在 `provenance.reused_fields` 与 `provenance.recomputed_fields` 记录边界。同哈希历史路线不是当前勘察的结论。

## 禁止的编排

- 在勘察阶段写坐标，或为了拿坐标先跑量测、先裁小图。
- 先逐元素处理，再回头决定总体路线。
- 用一个标签盖住整幅图的所有区域。
- 因对象源图专有就默认切；因它看起来简单就默认画。
- 把已知污染写成待确认项，等切完再处理。
- 概要没写完就进入备料，或备料中途推翻概要而不告知用户。
- 用户未决定连续场前景深度时继续生成、裁剪或合成。
- 复用历史 manifest 的路线冒充新勘察。
