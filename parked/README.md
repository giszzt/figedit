# 停在这里的东西

## read_figure.py —— 候选枚举，未过门，不要接线

目标是给图上每个对象编号，让模型用编号点名而不是打坐标。

**实测结果（`tests/eval_read_figure.py`，32 个历史任务 2047 个真值对象）**

| | |
|---|---|
| 不设上限时能指到 | 85.0%（候选最多 1946 个，标号图没法看） |
| 候选压到 220 时能指到 | 75.8% |
| 门槛 | 能指到 ≥99%，候选 ≤130 |

**失败的根因**：连通域把画面丰富的具象对象打成碎片。esa-iss 那种任务图里全是照片式徽章，最好的候选只覆盖真值的 12%，整张图 5.4%。而扁平纯色图标它做得很好（swandata、agentbench、tu1、dataprep 都是 100%）。

**试过并且无效的办法**：
- 用 `probe_geometry.image_profile` 的 `flat_design_score` 做弃权判断。32 张图没有一张被判为弃权，包括失败最惨的那几张——那个分数量的是背景平整度，esa-iss 是纯色暗底加照片徽章，背景很平，分数很高。**它量不出"对象是不是具象的"。**
- 提高候选上限。85% 是生成器本身的天花板，不是排序或截断造成的。
- 按 objectness 排序再截断。排序质量太差，加候选反而更差（220 上限 54% → 400 上限 70% → 无上限 85%）。

**下次要接着做的话，先解决"具象对象整体分割"这一个问题**，别再调连通域参数。评测脚本 `tests/eval_read_figure.py` 保留，改完直接重跑对照上面的数字。

**不要因为它看起来快完成了就接线。**76% 的能指到率意味着模型看完标号图仍有四分之一的对象要手工量，那比不给标号图更慢——它多花了看图的时间。
